# Как вшить рисунки, таблицы и графики в статьи для RAG — и чем заменить GROBID без Docker

Документ к дополнительному шагу `08_extract_assets.py` + `multimodal.py`. Состояние сведений: 16.10.2026.

Обозначения: **✔** — сверено с документацией или источником при подготовке документа; **◦** — из общих знаний, перед решением проверьте сами.

---

## 0. Коротко

1. Текстовая LLM «читает» только токены. Значит, в индекс и в контекст должен попасть **текст**, который заменяет рисунок или таблицу. Оригинал (PNG, CSV) хранится рядом, в метаданных чанка.
2. Базовый вариант без моделей: **подпись + таблица в Markdown + упоминания в тексте**. Он уже даёт много: в научных статьях подпись обычно несёт главный вывод рисунка.
3. Следующий уровень: **описание рисунка и данные с графика моделью зрения (VLM)**, вшитые на место рисунка. Это дороже и может ошибаться, поэтому всё помечается как «сгенерировано автоматически».
4. Максимальный уровень: **мультимодальный индекс** или передача **самой картинки** в генератор, если основная модель мультимодальная.
5. Для вашего репозитория нужны два шага: включить координаты фигур (`teiCoordinates`) и добавить шаг 8. Если GROBID/Docker недоступен, шаг 8 работает только на PyMuPDF (`--layout pymupdf`).

## 1. Принцип: два разных вопроса

| Вопрос | Что нужно |
|---|---|
| **Найдёт ли поиск** этот рисунок/таблицу? | Текст, по которому считается эмбеддинг: подпись, описание, ключевые числа, упоминания, название раздела |
| **Сможет ли генератор** правильно ответить по нему? | Точное содержимое: таблица целиком (Markdown/HTML/CSV) или сама картинка для мультимодальной модели |

Отсюда рабочий шаблон **«summary для поиска, оригинал для генерации»**: в индекс идёт короткий текст, а при попадании в top-k в контекст подтягивается полная таблица или картинка. Модуль кладёт в каждый чанк и текст, и `image_path`.

## 2. Что в репозитории сейчас и что нужно поменять

- ✔ `03 run grobid.py` передаёт `"teiCoordinates": ""` — координаты **выключены**. Без них TEI говорит, *что* на странице есть рисунок, но не *где*, и вырезать его из PDF нельзя.
- ✔ Формат координат GROBID: `coords="страница,x,y,w,h"` (x, y — верхний левый угол, начало в левом верхнем углу, страницы с 1, несколько боксов через `;`). Размеры страниц лежат в `<facsimile>`. GROBID использует CropBox, при его отсутствии MediaBox, поэтому при расхождении с PyMuPDF координаты масштабируются (модуль это делает).
- ✔ `teiCoordinates=figure` включает координаты и для рисунков, и для таблиц; `ref` — для ссылок на них в тексте.
- Таблицы и рисунки **не входят** в задачу baseline (README). Шаг 8 читает результаты шагов 1–3 и ничего в них не меняет, замеры времени и качества не затрагиваются.
- ✔ В README указан образ `0.9.0`; по текущей документации стабильная версия — `0.9.1` (`grobid/grobid:0.9.1-crf`, `…-full`).

**Как включить координаты** (любой из двух способов):

```bash
# A. Рекомендуется: отдельный запрос, baseline-TEI в data/tei не перезаписывается
python 08_extract_assets.py --regrobid          # результат: data/tei_coords/<id>.tei.xml
```

```python
# B. Патч шага 3 (изменит baseline — тогда перезапишите метки прогона и замеры).
# В requests словарь не умеет повторять ключ, поэтому data — список пар:
params = [("consolidateHeader", args.consolidate_header),
          ("consolidateCitations", args.consolidate_citations),
          ("includeRawCitations", "1"),
          ("teiCoordinates", "figure"), ("teiCoordinates", "ref")]
```

## 3. Таблицы: способы

| # | Способ | Как | Плюсы | Минусы |
|---|---|---|---|---|
| T1 | **Разметка издателя (JATS/XML)** | `<table-wrap>` → `<table>` | Идеальная структура, подписи, сноски | Есть не у каждого источника; у вас JATS намеренно используется только для эталона (README) |
| T2 | **PyMuPDF `find_tables()`** | Сначала по линиям, затем `strategy="text"` для таблиц без линий | Быстро, без моделей, уже в зависимостях | Объединённые ячейки, многоуровневые шапки, таблицы на двух страницах — слабо |
| T3 | **GROBID TEI** | `<figure type="table">` с `<table>` | Бесплатно в составе TEI | Структура ячеек часто плоская или отсутствует ◦; модуль берёт её как запасной вариант |
| T4 | **Модели структуры таблиц** | Docling (TableFormer), MinerU, Marker | Лучше с объединёнными ячейками и шапками | Тяжёлые модели, GPU желателен, свои лицензии (раздел 8.2) |
| T5 | **VLM по картинке таблицы** | Вырезка → «перепиши в Markdown» | Работает со сканами и сложными шапками | Стоимость; может «исправить» или придумать значение — поэтому в промпте запрет и метка `?` |
| T6 | **Camelot / pdfplumber / Tabula** ◦ | Правила по линиям или расположению слов | Предсказуемо, подстраивается руками | Подбор параметров под журнал; Tabula требует Java |
| T7 | **Картинка как есть** | Мультимодальный эмбеддинг и/или передача в генератор | Не теряется ничего | Нельзя искать по числам; нужен мультимодальный генератор |

**Что делает модуль:** T2 → затем T3 → затем (по флагу `--vlm-tables`) T5. Источник каждой таблицы записывается в `table_source`.

### Формат представления таблицы

| Формат | Когда |
|---|---|
| **Markdown** | Простые таблицы, до ~30 строк; LLM читают его уверенно. Используется в модуле |
| **HTML** (`<table>`, `rowspan`, `colspan`) | Объединённые ячейки и многоуровневые шапки: структура не теряется |
| **CSV/JSON** в метаданных | Если нужны вычисления или показ таблицы пользователю. Модуль пишет `<asset>.csv` |
| **По строкам**: «Группа = A; N = 10; AUC = 0,81» | Широкие таблицы: каждая строка самодостаточна для эмбеддинга ◦ |
| **Краткое резюме** (LLM) | Добавка к основному представлению для поиска; не замена |

Практики: подпись и сноски хранить вместе с таблицей; при нарезке длинной таблицы **повторять шапку** (модуль так и делает) и не резать строку пополам; сверять число строк и столбцов с картинкой хотя бы на выборке.

## 4. Рисунки и графики: способы

Сначала определите тип: **график** (числа), **схема/блок-схема** (структура), **фото/микроскопия/медицинское изображение** (визуальные признаки), **картинка с текстом** (скриншот, подпись внутри изображения).

| # | Способ | Что получаем | Замечания |
|---|---|---|---|
| F1 | **Подпись + упоминания в тексте** (`<ref type="figure">`) | Текст, уже написанный авторами | Бесплатно и надёжно; не содержит значений с графика. Уровень L0 модуля |
| F2 | **VLM-описание** | Тип рисунка, оси, группы, видимые тренды, текст на рисунке | Уровень L1. Промпт ограничивает: только видимое, без клинических выводов, нечитаемое не угадывать |
| F3 | **График → таблица данных** | Приблизительные значения точек/столбцов | Специализированные модели (DePlot, MatCha, UniChart ◦) или обычный VLM. Числа приблизительны — в модуле они помечаются `~` и подписью «approximate». Точные значения брать из текста и таблиц статьи |
| F4 | **OCR** (Tesseract, PaddleOCR, Surya ◦) | Метки осей, легенды, надписи | Для схем и картинок с текстом; современные VLM обычно справляются сами |
| F5 | **Мультимодальные эмбеддинги** (CLIP/SigLIP ◦, мультимодальные API эмбеддингов) | Поиск по картинке и по тексту в одном пространстве | Хуже понимает мелкие подписи, числа, оси; хорош для фото и схем |
| F6 | **Поиск по образам страниц** (ColPali/ColQwen ◦) | Страница целиком как картинка, без парсинга | Обходит ошибки парсера, но тяжёл по хранилищу и требует мультимодального генератора |
| F7 | **Картинка в генератор** | Генератор видит оригинал | Лучший ответ на вопросы «что на рисунке», если генератор мультимодальный |

**Важное про PDF.** Графики из matplotlib, R и Excel в PDF обычно **векторные**, а не встроенные картинки. `page.get_images()` их не видит; модуль использует `cluster_drawings()` и склеивает векторные кластеры с растровыми картинками.

**Медицинский контекст.** Описание — это «что нарисовано», а не интерпретация. Ни одна автоматическая подпись к снимку, гистологии, ЭКГ не должна попадать в ответ как клинический вывод; в блоке она помечена как автоматическая. Это согласуется с границами baseline («медицинские выводы не входят в задачу»).

## 5. Куда и как вшивать: архитектуры

| Архитектура | Суть | Что нужно | Реализовано |
|---|---|---|---|
| **A. Inline-текст** | Блок рисунка/таблицы стоит в тексте статьи на своём месте (после абзаца, где он идёт) | Только текстовые эмбеддинги | ✅ `data/rag/<id>.md` |
| **B. Отдельные чанки на актив** | Каждый рисунок/таблица — свой чанк (подпись + содержимое + упоминания), не смешивается с соседним текстом | То же | ✅ `<id>.chunks.jsonl` |
| **C. Multi-vector** | В индекс идёт короткое резюме, при попадании в контекст подтягивается оригинал из хранилища документов | Хранилище «id → оригинал» | Частично: оригинал — `image_path` и `.csv`; хранилище подключаете вы |
| **D. Мультимодальный индекс** | Эмбеддинги картинок рядом с текстовыми | Мультимодальная модель эмбеддингов | Вырезки готовы (`image_path`), эмбеддинг — на вашей стороне |
| **E. Образы страниц** | Индекс страниц как картинок | ColPali-подобная модель | Нет |

Рекомендуемый порядок внедрения для вас: **A + B** (работает на любой основной модели) → добавить VLM-описания → при мультимодальном генераторе подключить передачу `image_path` (C/F7).

### Как выглядит вшитый блок

```markdown
Prior work exists. Figure 1 shows the design.

<!-- asset:begin id=fig_0 type=figure page=3 -->
**Figure 1.** Study design with two arms.

*Image description (auto-generated from the image, may contain errors):* Flow diagram of ...

*Text visible in the image:* Arm A / Arm B

*Image file:* `assets/PMC123/fig_0.png`
<!-- asset:end -->
```

Маркеры `asset:begin/end` позволяют любому вашему чанкеру не разрезать блок.

### Метаданные чанка (`chunks.jsonl`)

```json
{"chunk_id": "PMC123#0004", "article_id": "PMC123", "type": "table", "section": "Results",
 "text": "<!-- asset:begin ... -->**Table 1.** Outcomes by arm.\n\n| Arm | N |\n...",
 "asset_id": "tab_0", "label": "Table 1", "page": 5, "image_path": "assets/PMC123/tab_0.png",
 "layout_source": "grobid-tei+coords", "table_source": "pymupdf-lines", "article_title": "..."}
```

`type` ∈ `text | figure | table`. Индексируйте поле `text`, а при формировании промпта используйте `image_path`/CSV по необходимости. В чанк рисунка/таблицы дополнительно добавлены упоминания из основного текста («Mentioned in the text»), чтобы вопрос, сформулированный словами абзаца, находил и сам рисунок.

## 6. Модуль `08_extract_assets.py`

### Установка

Новых зависимостей нет: `requests` и `pymupdf` уже в `requirements.txt`. Рекомендуется `pymupdf>=1.24.3` (нужны `find_tables`, `cluster_drawings`; модуль проверяет наличие методов и не падает на старых версиях, но тогда находит меньше).

Файлы положите рядом с `common.py`: `multimodal.py`, `08_extract_assets.py`, `test_multimodal.py`. Добавить в `run_all.sh`: `python 08_extract_assets.py --regrobid`.

> В GitHub-списке файлы названы с пробелами (`03 run grobid.py`), а в README — с подчёркиваниями. Модуль импортирует `common` (а при его отсутствии `res_common`), поэтому у него «нормальное» имя `multimodal.py`; CLI вызывайте как `08_extract_assets.py`.

### Режимы геометрии (`--layout`)

| Режим | Когда | Как находит рисунки и таблицы |
|---|---|---|
| `auto` (по умолчанию) | Всегда | Берёт лучшее из доступного по цепочке ниже |
| 1. `grobid-tei+coords` | Есть TEI с координатами (`--regrobid`) | Боксы из TEI; бокс фигуры расширяется до касающейся графики (`--no-refine` отключает) |
| 2. `grobid-tei+pymupdf-match` | Есть обычный TEI шага 3 без координат | Порядок текста и подписи — из TEI, положение — эвристикой PyMuPDF; сопоставление по номеру («Figure 3») |
| 3. `pymupdf-only` | GROBID/Docker недоступен (`--layout pymupdf`) | Подпись «Figure N»/«Table N» + ближайшая графика или таблица с линиями; текст — блоки PyMuPDF |
| `grobid` | Нужно строго TEI | Ошибка, если TEI нет |

Если GROBID не отвечает при `--regrobid`, модуль не падает, а переходит на следующий режим.

### Примеры

```bash
python 08_extract_assets.py --regrobid                          # без внешних моделей
python 08_extract_assets.py --layout pymupdf                    # Docker не работает
python 08_extract_assets.py --regrobid --vlm anthropic --vlm-model claude-sonnet-5-5 --vlm-tables --lang ru
python 08_extract_assets.py --vlm openai --vlm-base-url http://localhost:11434/v1 --vlm-model <модель>
```

`--vlm anthropic` берёт ключ из `ANTHROPIC_API_KEY`; `--vlm openai` работает с любым OpenAI-совместимым сервером (ключ — `VLM_API_KEY`, для локальных не нужен; для новых моделей OpenAI задайте `VLM_TOKEN_PARAM=max_completion_tokens`). Имя модели укажите сами: список меняется. Ответы кэшируются в `data/assets/vlm_cache.jsonl`, повторный запуск не платит за то же самое.

Отправка вырезок во внешний API означает передачу содержимого статей третьей стороне. Для открытых PMC-статей это допустимо; для закрытых документов используйте локальную VLM.

### Что пишется

```
data/tei_coords/<id>.tei.xml     TEI с координатами (только с --regrobid)
data/assets/<id>/fig_0.png …     вырезки рисунков и таблиц
data/assets/<id>/tab_0.csv       таблицы, если структура извлечена
data/assets/<id>/assets.json     все поля актива (источник, заметки, ответ VLM)
data/rag/<id>.md                 статья с вшитыми блоками
data/rag/<id>.chunks.jsonl       чанки для индекса
results/assets_summary.csv       найдено рисунков/таблиц, сколько с картинкой/структурой, вызовов VLM,
                                 а также число <fig> и <table-wrap> в JATS для сверки полноты
```

Число `<fig>`/`<table-wrap>` из JATS используется **только для сверки полноты**, в конвейер текста оно не попадает — граница «JATS = эталон» из вашего README сохраняется. Расхождение может быть законным (дополнительные материалы, группы рисунков).

### Известные ограничения (читайте до запуска на корпусе)

- **Что проверено, а что нет.** Логика разбора TEI, пересчёт координат, сборка Markdown, чанкер, клиенты VLM (на подставных ответах) и все три режима геометрии прогнаны тестами; PyMuPDF при этом был **заменён заглушкой**, потому что в среде подготовки не было сети. Поэтому **реальные вызовы PyMuPDF (`find_tables`, `cluster_drawings`, `get_pixmap`) и реальный GROBID на настоящих PDF не проверены**. Первый прогон начните с `--limit 3` и посмотрите вырезки глазами.
- Бокс фигуры в TEI может покрывать лишь подпись и текст внутри графика (у графики своя геометрия). Модуль объединяет `figure` и вложенные `graphic` и затем расширяет бокс до касающейся графики; на нестандартных макетах проверьте вручную.
- Таблица на нескольких страницах: обрабатывается только первая страница (пометка в `notes`).
- Повёрнутые страницы не пересчитываются.
- `pymupdf-only`: таблицы находятся **только с линиями** и только с подписью «Table N» (регулярное выражение для английских подписей). Рисунки без подписи отбрасываются как декор (логотипы). Порядок текста в двух колонках приблизительный — для текста в этом режиме лучше взять Docling/MinerU (раздел 8.2).
- Описания и числа VLM могут быть неверными; в Markdown они всегда подписаны как автоматические. Для ответов с цифрами используйте таблицы и текст статьи.
- Лицензии картинок. Лицензия статьи в PMC не всегда распространяется на каждый рисунок (рисунки могут быть перепечатаны с разрешения). Если вы публикуете или передаёте вырезки, проверяйте условия для рисунков, а не только для статьи; текст README про лицензии относится и сюда.

## 7. Контроль качества

1. **Полнота:** `assets_summary.csv`: `n_figures`/`n_tables` против `jats_fig`/`jats_table_wrap`.
2. **Вырезки:** посмотреть 10–20 PNG случайных статей; доля обрезанных или захвативших лишнее — главный показатель геометрии.
3. **Таблицы:** для 5–10 таблиц составить эталон вручную (из JATS, с проверкой по PDF) и посчитать долю совпавших ячеек и корректность числа строк/столбцов.
4. **Сквозной тест RAG:** 20–30 вопросов, ответ на которые есть **только** в таблице или на рисунке. Метрики: попадает ли актив в top-k и верен ли ответ — с вшитыми блоками и без. Это единственная проверка, показывающая реальную пользу.
5. **VLM:** выборочно сверять описание с рисунком; особенно числа в `data_table_markdown`.

## 8. Если Docker не работает

### 8.1. Остаться на GROBID, но без Docker

| Вариант | Как | Замечания |
|---|---|---|
| **Podman** ◦ | `podman run --rm --init --ulimit core=0 -p 8070:8070 docker.io/grobid/grobid:0.9.1-crf` | Не требует демона и root; те же образы. Для DL-образа нужен проброс GPU |
| **Apptainer / Singularity** ◦ | `apptainer pull docker://grobid/grobid:0.9.1-crf`, затем запуск `.sif` | Типично для кластеров. Файловая система образа только для чтения — могут понадобиться `--bind` на каталоги для временных файлов и логов |

### 8.2. Аналоги GROBID

Важно: **это не «заменитель один к одному»**. GROBID специализирован на научных статьях и отдаёт структурированные заголовок, авторов, **библиографию по полям** (то, что оценивает ваш baseline). Перечисленные ниже инструменты в первую очередь превращают страницу в Markdown/JSON с таблицами и рисунками; структурированных ссылок «из коробки» они, насколько я знаю ◦, не дают — это нужно проверить. Для рисунков и таблиц многие из них сильнее GROBID.

### 8.3. Как выбрать и как встроить

- **Нужны таблицы и рисунки, ссылки не критичны:** Docling или MinerU для текста и таблиц; шаг 8 можно оставить как слой «вырезка + VLM + чанки» (`--layout pymupdf`) либо заменить его ввод на `docling_document.tables/pictures`.
- **Нужен тот же набор метрик, что в baseline (название, авторы, год, DOI, аннотация, разделы, ссылки):** GROBID остаётся лучшим выбором. Для ссылок вне GROBID — запросы к Crossref/OpenAlex по DOI/названию и отдельный разбор строк ссылок (например, AnyStyle ◦) — это отдельная оценка.
- **Строго один инструмент и без Docker:** Docling (MIT) как первый кандидат. Заведите адаптер, записывающий результат в **тот же JSON**, что `04_parse_tei.py` (поля `title`, `authors`, `year`, `doi`, `abstract`, `section_headings`, `references`), тогда `06_evaluate.py` и `07_timing_report.py` сравнят инструменты на вашем ручном эталоне. Не доверяйте чужим бенчмаркам больше, чем 10–15 вашим размеченным статьям.
- Лицензионная проверка нужна для **весов моделей** отдельно от лицензии кода, особенно у Marker и MinerU.

Кусочек для Docling (API меняется между версиями — сверяйтесь с документацией установленной версии ◦):

```python
from docling.document_converter import DocumentConverter, PdfFormatOption
from docling.datamodel.base_models import InputFormat
from docling.datamodel.pipeline_options import PdfPipelineOptions

opts = PdfPipelineOptions()
opts.generate_picture_images = True     # сохранить вырезки рисунков
opts.images_scale = 2.0
conv = DocumentConverter(format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=opts)})
doc = conv.convert("data/pdf/PMC123.pdf").document
md = doc.export_to_markdown()
for t in doc.tables:   df = t.export_to_dataframe(doc)    # таблица как DataFrame
for p in doc.pictures: img = p.get_image(doc)             # PIL-картинка
```
