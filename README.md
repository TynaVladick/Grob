# Базовая линия GROBID на открытых медицинских статьях (PMC)

Что делает пайплайн: берёт 20–30 PDF из PMC Open Access, извлекает **название, авторов, год, DOI, аннотацию,
заголовки разделов и список литературы** локальным GROBID, сравнивает результат с ручным эталоном
(10–15 статей) и фиксирует время и ошибки. Таблицы, проверка цитат и медицинские выводы **не входят** в задачу.

Все файлы лежат внутри этой папки `res/` (другую корневую папку можно задать переменной `RES_DIR`).

## Поиск и скачивание статей по запросу на русском (`search_articles.py`)

Отдельный модуль (пакет `litsearch/`), который готовит корпус PDF для пайплайна ниже. Основной сценарий:

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY="..."            # ИИ, строящий запросы (или OPENAI_API_KEY + LLM_MODEL)
export NCBI_EMAIL="you@example.org"       # идентификация для NCBI и Unpaywall (иначе Unpaywall выключен)
python search_articles.py "влияет ли метформин на риск деменции у пожилых"
```

Что происходит:

1. **ИИ строит запрос.** Русская фраза превращается в структурный план: 2–4 понятия (по PICO), для каждого —
   заголовки MeSH и синонимы, плюс фильтры, если вы их подразумевали («за последние 5 лет», «рандомизированные»).
   ИИ возвращает JSON через tool calling, а *строки запросов собирает код*: синтаксических ошибок в итоговом
   запросе не бывает. Заголовки MeSH дополнительно проверяются в PubMed, несуществующие переводятся в обычные слова.
2. **Диалог по фильтрам.** По основной базе (первая в `--sources`, по умолчанию PubMed) считается число результатов.
   Если вне диапазона `--min`–`--max` (по умолчанию 20–300), предлагаются варианты сузить/расширить запрос
   **с готовым числом статей по каждому** («только последние 5 лет → 410 ✓»). Можно ввести номера через запятую
   или написать по-русски («только РКИ без детей») — правку применяет ИИ. `ok` принимает запрос, `q` выходит.
   В неинтерактивном режиме или с `--auto` подбор идёт сам: сначала «мягкие» фильтры (годы, открытый доступ,
   люди), тип исследований — в последнюю очередь.
3. **Поиск по всем базам и объединение.** Один и тот же план переводится на синтаксис каждой базы;
   дубликаты склеиваются (DOI → PMID → PMCID → название), порядок — по reciprocal rank fusion.
4. **Автоскачивание** статей в открытом доступе, пока не наберётся `--max-download` (неудачные заменяются следующими).
   Каскад источников: PMC Cloud Service (S3, проверка md5 и лицензии) → Europe PMC → ссылки на OA-PDF из баз
   поиска → Unpaywall по DOI. Каждый файл проверяется на сигнатуру `%PDF` (страницы издателей отбрасываются).

Результат — папка `data/search_runs/<время>_<тема>/`: `plan.json` (план, точные запросы, число результатов),
`articles.csv` (все найденные статьи, статус загрузки, источник, лицензия, ошибка), `data/pdf/*.pdf`.
В GROBID-пайплайн: `RES_DIR=<папка> python "03 run grobid.py"`.

```bash
python search_articles.py "..." --dry-run                      # показать план и запросы к каждой базе, ничего не искать
python search_articles.py "..." --auto --max-download 20       # без вопросов
python search_articles.py "..." --sources pubmed,europepmc,openalex,semanticscholar --min 50 --max 500
python search_articles.py "..." --licenses "CC BY,CC0"         # из PMC скачивать только эти лицензии
python search_articles.py --plan-file plan.json --no-llm       # без ИИ: готовый план (формат ниже)
```

Формат `--plan-file` (то же, что лежит в `plan.json` → `plan`):

```json
{"interpretation_ru": "Метформин и риск деменции",
 "concepts": [{"label": "metformin", "mesh": ["Metformin"], "keywords": ["metformin", "glucophage"]},
              {"label": "dementia", "mesh": ["Dementia"], "keywords": ["dementia", "alzheimer*"]}],
 "filters": {"year_from": 2020, "study_types": ["rct", "meta_analysis"], "humans_only": true}}
```

Допустимые `study_types`: `rct`, `clinical_trial`, `meta_analysis`, `systematic_review`, `review`, `guideline`, `case_report`;
`languages` — коды `en`, `ru`, `de`, `fr`, `es`, `zh`.

### Источники поиска

| База | Статус | Ключ / лимиты | Особенности |
|---|---|---|---|
| **PubMed** | подключена (основная) | `NCBI_API_KEY` необязателен: 3 → 10 запросов/с | MeSH, типы публикаций, `free full text`, самый точный синтаксис |
| **Europe PMC** | подключена | без ключа | PubMed + PMC; сразу знает, что в открытом доступе (`OPEN_ACCESS:y`); препринты исключены |
| **OpenAlex** | подключена | с 2026 г. бюджет: без ключа ≈ $0.10/день, бесплатный `OPENALEX_API_KEY` — $1/день | булев поиск по названию+аннотации, ссылки на OA-PDF; нет MeSH и фильтра «только люди» (тип исследования ищется словами) |
| **Semantic Scholar** | подключена | `S2_API_KEY` необязателен, без него частые 429 | bulk-поиск с булевым синтаксисом; выдача — по цитируемости, не по релевантности; нет фильтров «люди/язык/аннотация» |
| **Google Scholar** | **не подключён** | — | официального API нет, автоматические запросы запрещены условиями использования и блокируются капчей. Единственный законный путь — платный посредник (SerpApi и т. п.); при желании добавляется как ещё один `Provider` |
| Crossref, CORE, BASE, Lens.org | не подключены | — | легко добавить: достаточно класса с методами `render / count / search` в `litsearch/providers/` и записи в `REGISTRY` |
| Scopus, Web of Science, Dimensions | не подключены | платные, институциональный доступ | — |

Подключить другую базу: наследуйтесь от `litsearch.providers.base.Provider`, реализуйте `render(plan)`, `count(plan)`, `search(plan, limit)`
и добавьте класс в `litsearch/providers/__init__.py`.

### Ограничения и статус проверки

* Скачиваются только статьи, **легально выложенные в открытый доступ**; доля платных статей скачана не будет
  (причины — в колонке `error`). Обход paywall не выполняется.
* Логика (сборка запросов, разбор ответов, объединение, диалог, каскад загрузки, разбор ответов ИИ) покрыта
  `test_litsearch.py` на подменённом HTTP. **Живые запросы к API при разработке не выполнялись** (в среде разработки
  внешняя сеть закрыта), поэтому перед серьёзным использованием запустите `--dry-run` и один пробный поиск,
  особенно для Europe PMC / OpenAlex / Semantic Scholar: их синтаксис сверен с документацией, но не с реальными ответами.
  Если OpenAlex отклонит фильтр `title_and_abstract.search`, модуль автоматически переключится на параметр `search`.
* Из записей берутся метаданные (название, авторы, журнал, год, идентификаторы), без аннотаций: для PubMed используется `esummary`.
* Тесты: `python -m pytest test_litsearch.py -q` (или просто `python test_litsearch.py`).

## Установка

```bash
pip install -r requirements.txt          # requests, pymupdf
export NCBI_EMAIL="you@example.org"      # желательно: идентифицирует вас для NCBI
export NCBI_API_KEY="..."                # необязательно: ускоряет E-utilities
```

GROBID (одним контейнером; актуальные теги смотрите в документации GROBID):

```bash
# лёгкий образ, только CRF-модели, CPU
docker run --rm --init --ulimit core=0 -p 8070:8070 grobid/grobid:0.9.0-crf
# полный образ с DL-моделями: точнее, но тяжелее (желателен GPU)
docker run --rm --gpus all --init --ulimit core=0 -p 8070:8070 grobid/grobid:0.9.0-full
```

Образ (`crf` или `full`), число ядер и GPU влияют и на качество, и на время — зафиксируйте их через `--label`.

## Порядок запуска

```bash
python 01_select_and_download.py --n 30      # 1. отбор + загрузка (повторный запуск докачивает недостающее)
python 02_pymupdf_diagnostics.py             # 2. диагностика PDF (скан или текстовый слой, колонки)
python 03_run_grobid.py --label crf-0.9.0    # 3. GROBID, строго по одному PDF
python 04_parse_tei.py                       # 4. TEI -> поля
python 05_make_gold_drafts.py --n 12         # 5. черновики эталона  ->  ПРОВЕРИТЬ ВРУЧНУЮ

python 07_timing_report.py                   # 7. время и ошибки
```

## Откуда берутся статьи

PMC разрешает автоматическую загрузку только через определённые сервисы. С августа 2026 старые
OA Web Service (`oa.fcgi`) и FTP отключены; скрипт использует:

* **E-utilities (eSearch)** — только чтобы найти PMCID (фильтры `open_access`, `has_pdf`, лицензии CC BY/CC0, без эмбарго);
* **PMC Cloud Service** (S3-бакет `pmc-oa-opendata`, HTTPS без авторизации) — PDF, JATS XML и JSON-метаданные.

**Лицензия проверяется отдельно для каждой статьи** по `license_code` в её JSON-метаданных, а не только по
фильтру поиска. Отклоняются: лицензии вне списка `--licenses` (по умолчанию `CC BY`, `CC0`), авторские рукописи,
ретрагированные статьи, исторические OCR-сканы, статьи без PDF. Целостность PDF проверяется по md5 из метаданных.
Причины отказов — в `data/rejected.csv`, лицензии принятых статей — в `data/manifest.csv`.
Если вы будете публиковать или передавать корпус дальше, сохраните атрибуцию авторов и ссылку на источник и
убедитесь, что лицензия каждой статьи это допускает (для `CC BY-NC`/`ND`/`SA` условия другие).
Используя данные PMC, указывайте NLM как источник (условия: README бакета).

## Как составить ручной эталон (шаг 5)

`05_make_gold_drafts.py` создаёт `gold/<id>.json` из JATS XML той же статьи — это **заготовка, а не эталон**.
Для каждой из 10–15 статей:

1. Откройте `gold/<id>.json` и `data/pdf/<id>.pdf`.
2. Сверьте с тем, что напечатано в PDF: название; авторов (состав и фамилии); год публикации
   (`year`, а другие допустимые годы, например онлайн-публикация и номер журнала, — в `year_alt`); DOI;
   аннотацию; заголовки разделов (в порядке следования); ссылки (название, DOI, год, фамилия первого автора).
3. Исправьте расхождения. Запишите спорные места в `notes`.
4. Только после этого поставьте `"verified": true`. Файлы с `verified: false` в оценке не участвуют.

Повторный запуск шага 5 уже существующие файлы эталона **не перезаписывает**.

## Метрики

| Поле | Как сравнивается |
|---|---|
| Название, DOI, год | точное совпадение после нормализации (регистр, диакритика, пунктуация; DOI без `https://doi.org/`; год — любой из `year`/`year_alt`) → **доля правильных** |
| Авторы | множество (фамилия + первая буква имени) → **precision / recall / F1** |
| Заголовки разделов | множество заголовков без нумерации → **precision / recall / F1** |
| Ссылки | «ссылка найдена», если совпал DOI, либо название похоже на ≥ 0,85, либо совпали фамилия 1-го автора и год → **precision / recall / F1** |
| Аннотация | среднее сходство текстов и token-F1 (точное равенство длинного текста не имеет смысла) |

Для сущностей выводятся micro-значения (TP/FP/FN суммируются по статьям) и macro-F1 (среднее по статьям).
Статья без результата GROBID считается пустым ответом (все поля — промахи); флаг `--skip-failed` исключает такие статьи.

## Что важно помнить при чтении результатов

* **Это базовая линия**, а не доказательство ускорения от распределения: один клиент, один экземпляр GROBID,
  последовательно, на вашем железе. Для будущего сравнения фиксируйте образ GROBID, `--label`, число ядер/GPU.
* Консолидация через внешние сервисы по умолчанию **выключена** (`--consolidate-header 0 --consolidate-citations 0`),
  чтобы измерять сам GROBID, а не сеть. Включение изменит и точность, и время.
* Первый запрос обычно медленнее (прогрев); `07_timing_report.py` даёт медиану и без первого документа.
* Метрика ссылок оценивает **обнаружение** ссылок, а не безошибочность всех их полей.
* Черновик эталона построен из JATS: если вы пропустите ручную сверку, получите проверку «GROBID vs XML издателя»,
  а не «GROBID vs статья». Поэтому `verified` ставится только вручную.
* Качество зависит от самого PDF. `02_pymupdf_diagnostics.py` помечает файлы без текстового слоя
  (`scanned_suspect`) и страницы в две колонки (эвристика), где порядок текста может нарушаться.
  OCR не выполняется ни здесь, ни в GROBID: такие PDF лучше исключить или обработать отдельно
  (в PyMuPDF для этого есть `page.get_textpage_ocr()`, нужен Tesseract).
* Выборка из 10–15 статей мала: доверительные интервалы широкие, различия в несколько процентных пунктов — шум.
